# Данные и provenance

Версия контракта: 0.1. JSON: UTF-8, конечные числа, неизвестное null. Пути относительно корня, хеши SHA-256. Все времена исполнения — ISO 8601 UTC. Динамические времена имеют отдельную шкалу и единицу.

## Наборы

| Каталог | Правила |
|---|---|
| data/acquisition/requests | Воспроизводимые запросы без credentials и подписанных URL |
| data/acquisition/astrobridge | Собственный workspace внешнего приложения; его манифесты не редактировать |
| data/raw, references/papers | Полученные оригиналы; неизменяемы после регистрации |
| data/kernels | Ядра, meta-kernel, временное покрытие, версии и SHA |
| data/interim | Восстановимые промежуточные преобразования |
| data/processed | Нормализованные версионируемые данные с единицами и происхождением |
| runs | Полные отдельные исполнения; завершённые записи не исправлять на месте |
| results | Производные проверенные продукты, ссылки на run_id и генератор |

## Паспорт параметра

`value`, `unit`, `source_id`, `source_locator`, `uncertainty`, `uncertainty_status`, `covariance_ref`, `status`. Для радиуса дополнительно определение; для гармоник — нормировка и опорный радиус; для вращения — полюс, оси, эпоха. `null` с draft означает «не получено», не нулевую неопределённость. Реальные состояния: origin, frame, epoch, time_scale, position_unit, velocity_unit, векторы r/v и источник.

## Запуск

`run_id` — уникальное исполнение; `experiment_id` — имя версии постановки; `scientific_id` — хеш конфигурации, кода, входов и версий среды (без времени исполнения). `status`: planned/running/completed/failed/cancelled/partial. Отдельный `validation.status`: passed/failed/not_run. Завершённое исполнение с failed validation не научно принято.

`manifest.json`: schema_version, IDs, UTC начала/конца, статус, data_kind, hashes входов и кода, окружение, git commit/dirty при наличии, wall/CPU, хеши выходов и причина ошибки. `config.resolved.yaml`: вся применённая конфигурация. `validation.json`: метрики, заранее заданные допуски, ограничения. `initial_conditions/`: точные старты. `results/`: исходы. `logs/`: события исполнения. `checkpoints/`: реальные состояния продолжения, если реализованы (L0 их не создаёт).

Минимальный контракт будущего научного исхода задан в `docs/templates/orbit_record.yaml`: старт, мера, q, вес, страта, seed/рандомизация, физика, интегратор, события, последнее валидное время, диагностика и стоимость. Это шаблон, не готовый каталог. `run_status` не подменяет `physical_outcome`; missing/failed не кодировать как escape.

ECSV — малые таблицы с единицами; Parquet — ансамбли с сопутствующей схемой единиц. HDF5/Zarr выбрать только при реальной необходимости. Для каждого научного рисунка нужны run_id, генератор, входы и хеш продукта. Полные траектории хранить для обоснованной подвыборки, а не всех орбит автоматически.

## Литература и доказательства

`references/source_manifest.json` различает локально прочитанные исходные документы и ссылки, лишь перенесённые из программы. `bibliography.bib` содержит начальные записи с непроверенным статусом. `docs/literature/evidence.csv` хранит утверждения первоисточников; `results/evidence/claims.csv` — собственные выводы.

`search_log.jsonl`: одна операция/строка, цель, провайдер, UTC, запрос/URL, результат, source_ids. `search_usage.json`: раздельные web_search_calls, page_fetch_calls, scientific_api_calls, downloads, paid_calls и credits. Не смешивать число запросов и списанные кредиты.

Резервное копирование: требуется отдельный носитель и проверка восстановления. До назначения пути в paths.local backup считается unconfigured; Git не заменяет копию runs/raw.
