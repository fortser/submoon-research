# 17. Реализация, форматы данных и воспроизводимость

## 17.1. Состав вычислительной системы

Нужны отдельные компоненты: каталог физических параметров; генератор состояний и весов; библиотека сил; интегратор и регистрация событий; система запусков и перезапусков; анализ; наблюдательная обработка; генерация таблиц и рисунков. Математическая модель отделяется от конкретного интегратора, чтобы проверка независимым методом не требовала переписывать весь проект.

Версии кода, компилятора и зависимостей фиксируются. Используется машинно-читаемый конфигурационный файл, а не ручное редактирование значений между сериями. Начальная эпоха, шкала времени, система отсчёта, единицы, нормировки гармоник и случайные seeds являются частью научных данных.

При расширении модели прежняя серия сохраняется отдельной версией. Нельзя перезаписать первоначальный атлас новым и затем сравнивать только удобные различия. Исторические ошибки исправляются с таблицей затронутых результатов.

## 17.2. Минимальная запись одного расчёта

| Группа полей | Что сохраняется |
|---|---|
| Идентификация | Хозяин, run_id, версия модели, конфигурация, контрольная сумма входа |
| Старт | Эпоха, декартовы координаты и скорости, элементы для справки, ориентация и спин |
| Статистический дизайн | Мера, распределение предложения, вес, страта, номер рандомизации, seed |
| Физика | Параметры тел, выбранные силы, источник и версия данных, сценарий неизвестных параметров |
| Численный протокол | Интегратор, допуски, обработка событий, контрольные интервалы |
| Исход | Время последнего валидного состояния, событие, причина, статус неопределённости |
| Диагностика | Минимальный перицентр, максимальный эксцентриситет, энергетические и моментные балансы, резонансные признаки |
| Стоимость | CPU/GPU-время, вычисления силы, объём записи, причины повторов |

Для первичного атласа не требуется хранить всю траекторию каждого тела с одинаковой высокой частотой. Для всех сохраняются исходы и компактные диагностические ряды; плотные траектории — для стратифицированной подвыборки, событий и резонансных кейсов. Частота записи должна разрешать исследуемый механизм; редкая запись не может служить доказательством отсутствия резонанса.

Наблюдательная запись содержит идентификаторы исходных кадров, калибровки и геометрии, маски, параметры фоновой модели, шаблоны поиска, инъекции, полноту и все причины отклонения кандидата. Возможность восстановить верхний предел важнее красивой иллюстрации одного кадра.

## 17.3. Проверочный выпуск перед научным масштабированием

Небольшой открытый пример должен запускаться на обычной рабочей станции и восстанавливать одну базовую орбиту, одно событие, одну карту небольшого ансамбля и одну оценку доли с заданными весами. Он проверяет воспроизводимость цепочки, а не заменяет производственный расчёт. Полный запуск может требовать кластера, но его конфигурации и сводные исходы должны быть доступны для независимого анализа.

Перед публикацией провести внутреннее воспроизведение другим исполнителем или независимым маршрутом расчёта: от чистых входных файлов до основных таблиц. Если такой проверки не было, это указывается, а не заменяется фразой «код открыт».
