# Восстановление выпуска 0.2.0

Основная копия: `C:/submoon-research-backup/v0.2.0-20261005-r2/`.
ZIP содержит рабочие научные оригиналы, код, конфиги и завершённые runs
на момент коммита ec20649. Первый пакет без суффикса r2 неполон по двум
русским исходным документам; использовать только r2.

SHA пакета: ca2857fb52d6b22d177d929379a0502eb627b4d73dfbb1616f08e498dd9aa926.
Wheel: submoon_research-0.2.0-py3-none-any.whl;
SHA: 523b150d0cd27dbb8d80a2099fc33239eeba3ca68a2ac51c7f8ba1650be0b34e.

1. Сверить SHA ZIP с receipt и results/evidence/backup_restore_v1.json.
2. Восстанавливать в новую папку командой
   `python scripts/release_workspace.py restore --package <ZIP> --destination <новая-папка>`.
   Существующий каталог не перезаписывается. Проверяются имена, размеры и SHA
   каждого из 6312 файлов; итог — restore.validation.json.
3. `.venv`, приватные пути и секреты не входят в пакет. Создать среду по
   pyproject.toml и сохранённому requirements/windows-py310-remediation-20261005.lock.txt.
   Для проверенного опыта восстановления использовалась текущая Python 3.10 .venv;
   установка всех зависимостей в чистую среду отдельно не проверялась.
4. Запустить project validate, build_stage_briefs --check, verify_l1_specification
   и project smoke, затем pytest и Ruff. L0 не заменяет численные ворота W2.

После упаковки итоговые отчёты/журнал дополняются отдельными аттестациями.
Git bundle сохраняет историю кода и эти финальные записи; ZIP сохраняет
научные данные, не включённые в Git. Восстановление ZIP не создаёт `.git`.
Полученный из bundle checkout нужно дополнить проверенными научными файлами
из ZIP. Секреты и локальные пути настраиваются отдельно.

Состав копии и проверка чистого checkout записаны в backup_restore_v1.json.
Пять старых служебных файлов checkout имеют только отличия CRLF/LF;
научные SHA-входы проходят строгую приёмку. C — отдельный том, физическая
независимость устройства не установлена. Планового автоматического backup
и защиты от потери обоих томов эта разовая копия не обеспечивает.
