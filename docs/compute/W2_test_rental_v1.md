Подготовлено 2026-10-06 для W2-T003. По прямому пожеланию пользователя
полные проверки и сравнительные прогоны перенесены с рабочего компьютера.
Предел подбора, сообщённый пользователем: $3; конкретная аренда ещё не создана.

## Конкретный план

Одна on-demand аренда, без spot/новых томов/платных повторных аренд.
AMD EPYC предпочтителен; >=16 `cpu_cores_effective`, >=32 GB RAM,
amd64/AVX, verified, reliability>=0.98, SSH, диск 20 GiB.
В поиске обнаружен EPYC 7702, оффер 51941434: 32 effective CPU,
32211 MB RAM, $0.11593/h с 20 GiB диска, трафик $0.01302/GB в каждую сторону.
Цены/доступность повторно проверяются непосредственно перед созданием.

Допустимая замена: один сервер с теми же минимальными условиями,
вычисления + диск <=$0.30/h, входящий/исходящий трафик <=$0.02/GB.
Образ Ubuntu 22.04, отдельная Python venv, закреплённые зависимости.
GPU может входить в предложение, но научные вычисления выполняются на CPU FP64.

Максимум 3 часа с момента создания. До 1 часа на первую сравнительную серию;
оставшееся время — установка, исправление инфраструктурной несовместимости,
проверка/выгрузка и завершение. Суммарная сравнительная работа <=3600 s;
повтор ошибочной серии возможен только в оставшемся суммарном времени.

Расход при верхних границах: compute+storage <=$0.90, трафик <=$0.40
при лимите 10 GB в каждую сторону. Резерв внутри общего потолка $3 — $1.70.
Пополнение баланса не входит. Бюджет — потолок, не целевой расход.
Оценка удалённой серии 15–60 минут предварительная; установку закладываем до
30 минут. Старый локальный benchmark 36 коротких случаев занял 135.17 s;
новые движки ещё не измерены. Новых нагрузочных тестов на компьютере пользователя нет.

## Проверки реального исполнения

Пакет содержит текущие исходники, конфигурации, необходимые малые данные и
прошлые доказательства; секреты/.git/.venv не передаются. SHA каждого файла и архива.
Проверяется фактическая affinity, cgroup CPU quota/RAM и доступная память.
Размер пула <=min(16,effective CPU,affinity,cgroup quota), один thread на worker.
Скорость движков сравнивается одним worker; отдельно одинаковый ансамбль
из 36 заданий на 1/2/4/8/16 процессах. Учитываются запуски worker и JIT.

Полный pytest/Ruff/validate/smoke предшествует реальной серии. Аналитические
стресс-отказы сохраняются как научный результат. Worker timeout не становится
физической потерей. Каждый child run <=600 s, общая серия <=3600 s.
Локальный ресурсный профиль не расширяется; удалённый запуск имеет отдельный
контракт и явно записанные ресурсы в manifest.

## Надзор и прекращение

Контроллер `scripts/vast_w2.py` использует Vast.ai CLI из навыка
`C:/Users/Taras/.agents/skills/vastai/SKILL.md`; SSH — выделенный существующий ключ.
API-ключ не отправляется на сервер. Локальный скрытый watchdog с периодом
30 s завершает аренду по дедлайну; metadata/PID заносится в runtime.
Основной агент проверяет статус, логи, расход и получение артефактов.

Таймаут получения SSH/установки — 30 минут: при неудаче выгрузить доступные
логи и удалить этот инстанс; второй сервер требует отдельного разрешения.
За 5 минут до трёхчасового дедлайна: остановить задания, попытаться выгрузить
частичные результаты, затем destroy. При недоступности сервера приоритет имеет
прекращение аренды в согласованный срок; потеря невыгруженного фиксируется.
Задержка биллинга/API учитывается резервом; YAML не является ограничителем провайдера.

Штатно: выгрузка новых W2 runs, проверка SHA и полноты, импорт без перезаписи
существующих runs, destroy именно созданного инстанса, подтверждение отсутствия
в списке ресурсов и отчёт затрат. Stop не считается завершением аренды.
