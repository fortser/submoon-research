# Поиск станций Vast.ai под задачу: vast_find

Решения W2-D023, W2-D025; задача W2-T017; предложение W2-P008. Бесплатно и только чтение:
анонимный endpoint, квота аккаунта не тратится, аренды нет. Аренда — по-прежнему
`vast_p2.py` после отдельного разрешения пользователя (`docs/compute_policy.md`).

**W2-D029 (2026-10-14): сейчас и далее только `verified` или `unverified`.**
`deverified` и неизвестные статусы исключаются из нового выбора, даже если перечислены
в старом профиле/approval. Исторические сырые снимки могут содержать такие записи, но
они не являются кандидатами. `unverified` не подтверждает исправность контейнера.

## Как пользоваться

| Действие | Как |
|---|---|
| Машины под P2-2a | двойной щелчок `find_p2_2a.bat` |
| Все замеченные активные предложения от 16 vCPU до $1/ч (не полный рынок) | двойной щелчок `find_all.bat` |
| Ограниченный мониторинг кандидатов P2-2a | `monitor_p2_2a.bat`: 3 опроса, пауза 30 с, общий предел 600 с |
| Предложение по свежему снимку, без аренды | `... scripts/vast_station_select.py --output scratch/<новое_имя>.json` |
| Другой профиль | `.venv\Scripts\python.exe scripts\vast_find.py --profile <имя> --open` |
| Список профилей | `... scripts\vast_find.py --list-profiles` |
| Без сети, по сохранённым данным | `... scripts\vast_find.py --profile p2_2a --replay <offers.json или *.json.gz>` |

Поиск идёт 1–3 минуты (предел `--max-seconds`, по умолчанию 180). Результат: таблица в
консоли и HTML-страница в браузере — сортировка по любой колонке, фильтры (целые машины,
verified, CPU из каталога, без грубых оценок, укладываются в срок, предел $/ч, поиск по CPU),
копирование ID предложения. Файлы: `data/interim/vast_find/<профиль>/latest.html`,
`latest.json`, `offers.json` (формат `vast_p2`), общая история машин
`data/interim/vast_find/history.sqlite3` (колонка «машина видна с»).

## Как устроено

1. **Профиль** `configs/compute/profiles/<имя>.yaml`: `requirements` — жёсткие требования
   (vCPU, доля машины, RAM, диск, $/ч, надёжность, статусы проверки, прямые порты, CPU по
   каталогу и минимальная скорость ядра, срок); `workload` — модель нагрузки (ядро-часы и самое
   долгое задание на P-ядре i9, параллельная эффективность, развёртывание, RAM на процесс,
   E-ядра); `rank_by` — `cost`, `hours`, `ref_core_price` или `price_per_core`.
2. **Поиск до насыщения** (`finder.sweep_collection`). Выдача анонимного endpoint неполна и
   зависит от формы запроса; признака полноты нет (W2-R018…R020): сервер берёт ограниченное
   число кандидатов окна цены (64; через аккаунт — 512), выбранных не по цене, фильтр цены
   работает по `dph_base`, рынок до $1/ч на ~85% занят. Поэтому найденное четырьмя проходами
   разной формы — все с фильтрами наличия и требований профиля — объединяется: `price` (окна
   цены с делением полной страницы), `exclude` (те же диапазоны с исключением уже увиденных
   машин, `machine_id notin`), `vcpu_bands` (диапазоны vCPU), `gpu_count` (одна / несколько
   GPU). Для узких профилей добавляется `relaxed`: более широкий фильтр vCPU/диска, затем
   те же строгие клиентские требования. Время и запросы распределяются между видами проходов.
   В шапке — статус `completed`/`partial`/`skipped`, вклад и причина остановки. Малый прирост
   последних двух **выполненных** проходов — лишь эвристика насыщения, не доказательство полноты.
   Если последние два прохода пропущены/оборваны, насыщение не оценивается; неполнота других
   проходов остаётся видимой и не превращается в гарантию полного обхода. Ошибка доступа/429 прекращает сессию. По замерам 2026-10-13 один проход видел 55–61%
   замеченного за день, два разных — 85%.
   Перебор «только по цене» (анонимно и через аккаунт) отвергнут: видит ~21% свободных и тратит
   квоту (W2-C044…C046).
3. **Каталог скорости CPU** `configs/compute/cpu_catalog.yaml`: скорость ядра относительно
   P-ядра i9-14900K (W2-T006), SMT, P/E-ядра. Значок у скорости: без значка — замер,
   `*` — оценка модели, `~` — грубая оценка семейства. Неизвестный CPU — `?`.
4. **Оценка** на каждое предложение: `T = setup + max(T_crit/s, CH/(s·N·e))`, `$ = T·$/ч`;
   «путь» — время задаёт самое долгое задание. Диапазон — из диапазонов профиля. Цена —
   при диске профиля: `dph_base + storage_cost·ГБ/720`.
5. **Перед арендой** `vast_p2.py rent` бесплатно перепроверяет машину по `machine_id`:
   занятые и подорожавшие предложения пропускаются без траты попытки. Сверяются идентификатор
   машины и все требования (CPU/архитектура, доля, RAM, диск, тип контракта, статус, надёжность,
   цена с диском и прогноз срока). Ошибка перепроверки **блокирует** аренду, а не разрешает create.

## vast_p2 и approval

`vast_p2.py offers` ищет тем же поиском. Поля approval задают пределы поверх профиля:
`min_effective_cpus`, `max_hourly_usd`, `disk_gb`, `min_ram_gb`, `min_reliability`,
`cpu_name_regex`, `max_hours`. Новые поля:

- `allow_gpu: true` — разрешить GPU-инстансы. Вычислительные предложения Vast.ai почти всегда
  GPU-инстансы, а `num_gpus=0` — дисковые контракты (W2-P008); без этого поля поиск аренды пуст.
- `profile: p2_2a` — оценка часов и $ на серию и ранжирование по стоимости серии.

## Ограниченный мониторинг и выбор (W2-T018)

`vast_find.py --profile p2_2a_station --cycles 3 --interval 30 --max-seconds 120
--session-seconds 600` — конечная сессия, не фоновая служба. Снимки и изменения сохраняются
в `data/interim/vast_find/sessions/<session_id>/`; `latest.*` — только текущий вид.
«Не замечено повторно» не означает «занято». Старые предложения не подмешиваются в новый выбор.

`p2_2a_station` отделён от широкого профиля `p2_2a`: ≥64 доступных vCPU, доля ≥95%,
RAM ≥64 ГБ, надёжность ≥0.97, verified/unverified (W2-D029), поисковый предел ≤$0.75/ч с диском 60 ГБ.
Более высокая ставка допускается в поиск, если короткая серия дешевле; это не предел аренды.
Прогноз до 22.5 ч оставляет не менее 1.5 ч до общего предела 24 ч на завершение/выгрузку.
Это **поисковые границы, не согласованные расходы**. Скорость и параллельная эффективность
остаются оценками; допуск к полному стенду — только после базовой проверки.

`vast_station_select.py` принимает снимок не старше 15 минут, перепроверяет до 5 разных машин,
предпочитает verified среди удовлетворяющих требованиям и бюджету и пишет новый JSON с `approved:false`.
Для каждой машины срок аренды — округлённый вверх прогноз плюс 1.5 ч (не более 24 ч).
Проверяется `ставка × индивидуальный срок + резерв трафика ≤ $12`, а не только $/ч.
Существующий файл не заменяет. Режим `--offline` не подтверждает доступность. Скрипт не содержит
операций аренды, не читает старое разрешение и не создаёт approval.json.

`prepare_p2_2a.py --output scratch/<новый_каталог>` готовит локальный пакет SHA и `commands.json`
для **правильного** стенда `admission_p2_2.py` (9504 задания), не запускает расчёт и не вызывает API.
Старый `vast_p2.py deploy` пока относится к P2-1: один профиль поиска не меняет удалённый сценарий.
Порядок выполнения и ограничения — [предложение аренды v2](W2_P2-2a_rental_plan_v2.md).

## Ограничения

- Список не гарантированно полный (см. п. 2); для выбора машины этого обычно достаточно, а
  перед арендой предложение перепроверяется.
- Конфигурация и цены заявлены провайдером; доля CPU и скорость проверяются только после
  аренды (базовая проверка).
- Оценки скорости, кроме измеренных, приблизительны; семейства (`~`) — грубо.
  Параллельная эффективность в профиле P2-2a (0.78) — допущение до замера.
