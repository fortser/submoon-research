# Радар интересных рабочих станций Vast.ai

**16.10.2026, W2-D032:** пользователь отменил обязательные независимый watchdog до create и авто-destroy через полчаса без ответа и прямо поручил аренду найденной 9975WX для аппаратного теста. Остальные финансовые границы W2-D031 сохраняются; основной прогон не разрешён. Эта поправка имеет приоритет над историческими формулировками ниже и текстом, генерируемым радаром. [Действующее разрешение](trial_rental_approval.md).

Задача W2-T026, решение W2-D031. Постоянное локальное read-only приложение: **каждые 15 минут**, персональная проверка сохранённой 9975WX и отдельный поиск выгодных аналогов. Автоматической аренды нет; разрешение на будущую проверочную аренду и обязательные gates — [trial_rental_approval.md](trial_rental_approval.md).

## Самое важное для пользователя и агента

- **Файл находок:** [interesting_stations.md](interesting_stations.md). По фразе пользователя «появился интересный вариант» читать его первым, затем `data/interim/vast_radar/latest.json`, UTC/heartbeat и исходный снимок.
- **Интерфейс:** <http://127.0.0.1:8765/>. Работает только при запущенном процессе радара; обновление страницы читает локальные данные, не опрашивает Vast.ai.
- **Запуск:** двойной щелчок `vast_radar.bat`. Если процесс уже существует, вторая копия не запускается, открывается страница. По умолчанию первый запуск в трее, без навязчивого открытия браузера.
- **Завершение:** меню значка в трее или кнопка «Завершить» на странице. Крестик браузера монитор **не останавливает**.
- **Автозапуск:** ярлык текущего пользователя в Windows Startup, при входе в систему (не до входа и не на чужих компьютерах). Выключение ПК завершает процесс; при следующем входе он восстанавливает историю/эпизоды.

## Установка и обслуживание

Из корня, в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements/windows-py310-radar-20261015.lock.txt
# Дополнение к существующей среде, не замена научного lock; набор monitor — в pyproject.toml.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_vast_radar.ps1 -StartNow
```

Установка создаёт/проверяет только свой `Submoon Vast Radar.lnk`, не меняет глобальную ExecutionPolicy, не требует admin и не перезаписывает ярлык другой установки. При переносе проекта сначала удалить старый автозапуск, затем установить из нового пути. Зависимости не обновляются в фоне.

```powershell
# Удалить автозапуск; уже работающий процесс остановить через UI отдельно
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_vast_radar.ps1 -Remove
# Только открыть страницу
.\.venv\Scripts\python.exe scripts/vast_radar.py --open
# Сохранённый статус, без сети
.\.venv\Scripts\python.exe -X utf8 scripts/vast_radar.py --status
# Один бесплатный цикл (не одновременно с постоянным сборщиком)
.\.venv\Scripts\python.exe -X utf8 scripts/vast_radar.py --once
```

Радар не зависит от открытого чата. Сеть/серверная выдача могут отказать; UI показывает ошибки/устаревание, применяет backoff. При спящем/выключенном ПК запросов нет. После пробуждения выполняется один просроченный цикл, не все пропущенные. Свободное окно короче интервала можно пропустить. Нельзя гарантировать обнаружение или резервирование.

## Индикация и управление

Значок: синий — поиск работает, зелёный — есть свежая подходящая станция, жёлтый — ошибка/устаревание/необходимость пересмотра, серый — пауза. Windows может скрыть его в меню дополнительных значков: при желании закрепить вручную. В таблице состояния поиска и каждого предложения показаны отдельно.

Меню/страница: проверить сейчас (ручные повторные запросы не чаще раза в минуту), пауза, звук, без звука на час, проверить звук, просмотрено, завершить. Состояние паузы/звука/эпизодов сохраняется. «Проверить звук» играет локальный звук Windows, не обращается к Vast.ai. Реальную слышимость/настройки устройства пользователь проверяет этой кнопкой. Радар не включает звук устройства и не обходит Windows mute.

Один звук на новый подтверждённый эпизод и не более одного за цикл, даже при нескольких находках. До звука данные атомарно записаны в SQLite/файл передачи. Смена offer_id той же machine/allocation не дублирует сигнал. После сбоя между commit и звуком возможен пропуск звука, но не потеря находки/спам при рестарте. Возврат после явно подтверждённой недоступности или снижения с неподходящей цены взводит новый сигнал. Неполный поиск/ошибка/отсутствие в выдаче **не** перевзводят уведомление и **не** означают занятость. Произвольные мелкие колебания цены не пищат: для перевзвода по цене требуется выход более чем на 5% выше нарушенного порога. Пока монитор выключен, звуков нет.

## Поиск и критерии

`configs/compute/vast_radar.yaml` — единый конфиг. Под ним неизменённый finder/profile `p2_2a_station` и каталог `cpu_catalog.yaml`. Все 9975WX ищутся и в общей выдаче; машина 143224 проверяется отдельным запросом всех её offer_id до широкого поиска. Удачная точечная находка записывается/сигнализируется сразу, не дожидаясь широкого прохода.

Поиск анонимный read-only, без API-ключа и fallback на аккаунт; до 64 сетевых запросов за цикл, промежуток ≥1 с, timeout запроса 15 с, широкий поиск 120 с, дополнительно до 5 проверок других машин в общем бюджете. При access/rate limit оставшиеся запросы прекращаются; backoff до 2 ч. До уведомления каждый кандидат перепроверяется напрямую по машине.

Допуск: verified/unverified, amd64, compute/gpu/cpu, реальные cpu_cores_effective ≥64, доля ≥95% объявленного хоста, RAM ≥64 десятичных ГБ, диск ≥60 ГБ, reliability ≥0.97, прямой SSH-порт, известная скорость, полезных worker ≥28. `disk` и неизвестные типы/статусы исключены; machine 139652 исключена по W2-I031. Доля по API не доказывает физическую эксклюзивность CPU.

9975WX: ≤$0.65/ч. Аналоги: ≤$0.75/ч. Обе группы: верхняя модель P2-2a ≤16 ч, compute+disk ≤$11; с добавленными 0.5 ч проверки, 1.5 ч завершения и $1 трафика итог ≤$13. Неизвестная цена диска не заменяется удобным значением. Конфигурация не может повысить согласованные пределы $0.75/ч / $1 / 30 мин / $13, включить автоаренду или платные повторы.

Модель исходного finder: `T = setup + max(critical_path/speed, core_hours/(speed * workers * efficiency))`. Нагрузка — утверждённый полный P2-2a, 9504 задания, 280–350 i9 P-core·ч, длинный путь 12–13 ч, setup 1 ч, efficiency 0.78 — допущение. Не весь W2 и не пилот W1. Семейные оценки приблизительны; частота GHz и большое число SMT-потоков не являются замером скорости.

Серверная выдача неполна: используются несколько форм запросов нового finder, а не старый перебор только по цене. Признака полного рынка нет. Фильтры и CPU-модель общие с ручным поиском, поэтому рекомендации не расходятся из-за отдельной реализации.

## Хранение и проверяемость

- `data/interim/vast_radar/radar.sqlite3` (WAL) — метаданные, эпизоды/аллокации, циклы, события; это оперативное состояние, не научные данные.
- `latest.json` — текущая таблица; `heartbeat.json` — PID, фактическое время heartbeat, пауза, последняя/следующая проверка, ошибки. Старый файл после аварии не доказывает живой процесс. При чтении проверять UTC и PID.
- `launch.json` — последний запуск. `radar.log` — ротация 3×1 МБ плюс текущий лог. API-ключи и непубличные поля не сохраняются.
- `config-<sha>.json` — отдельные версии конфигурации, профиля, каталога и SHA исходников ядра. Версия связана с каждым циклом/находкой/снимком; старые snapshots не перезаписываются.
- `snapshots/<cycle>.json.gz` — публичные API-наблюдения; события/циклы и снимки старше 14 дней удаляются. Состояние подавления повторов/первой находки не удаляется.
- Общий предел 2 GiB: при достижении — пауза и ошибка, а не бесконтрольная запись. SQLite может сохранять выделенные страницы после DELETE; при необходимости обслуживание VACUUM — только после штатной остановки и резервной копии.
- Один сборщик защищён OS-lock, освобождаемым при аварии; PID-файл сам не является блокировкой. Статус процесса регистрируется в `tracking/runtime.json`, который остаётся реестром, а не источником доказательства живости.

Пять календарных дней без первой подходящей находки → видимый запрос пересмотра, без повышения бюджета и без остановки поиска. Дата не сбрасывается при рестарте/выключении, ручное удаление БД — потеря истории и подавления повторов, не штатный способ перезапуска.

Локальный HTTP слушает **только 127.0.0.1**, команды защищены случайным token, проверками Host/Origin и отсутствием CORS; нет внешних CDN. Не открывать порт наружу. Это UI текущего пользователя, не многопользовательский защищённый сервер.
