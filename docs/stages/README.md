# Полные рабочие досье этапов

Каждое досье объединяет **полный, несокращённый научный раздел этапа**, обязательные входы/чтение, последовательность работ, комплект выходов и условия передачи. Неизвестные параметры и новые решения уточняются задачами и журналами; досье не притворяется готовым протоколом ещё не выполненного исследования.

Общая картина для всех этапов: [project_overview.md](../context/project_overview.md).

## Обновление и защита от расхождений

Канонический исходник остаётся единственным авторитетным полным текстом программы. `catalog.yaml` задаёт рабочий план и дополнительные связи каждого этапа; `source_index.json` содержит исходный SHA и размеры/хеши производных файлов.

```powershell
.\.venv\Scripts\python.exe scripts/build_stage_briefs.py --check
.\.venv\Scripts\python.exe scripts/build_stage_briefs.py
```

Первая команда только проверяет совпадение. Вторая пересобирает производные досье и точные общие выдержки из текущего исходника. Ручные научные уточнения сначала оформляются решением и меняют канонический документ/каталог при необходимости; правки только в сгенерированном досье будут обнаружены проверкой и потеряны при пересборке.

`project_overview.md` — краткий редакционный обзор; генератор его не переписывает. При изменении целей или архитектуры его обновляет координирующий агент. Для нового этапа читать его досье полностью; в той же сессии уже прочитанные неизменённые общие блоки повторно загружать не нужно.
