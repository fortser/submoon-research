## Блокировка журнала: почему снята

- Защищала только окно < 1 с внутри `track add` от второго одновременного писателя. От записи по устаревшему состоянию защищает `expected_revision`, от захвата чужой задачи — проверка владельца; обе остаются.
- По журналам (423 события на 2026-10-13) минимальный интервал между записями разных агентов — 127 с; одновременная работа была один раз (12.10, Claude и Pi).
- Цена: в песочнице Claude нет права удаления, поэтому каждая запись оставляла `tracking/.write.lock` (81 перенос в `scratch/claude/_to_delete`), успешная запись выглядела как ошибка.
- Замена: детерминированный `event_id` (повтор той же команды не создаёт дубля) и проверка после записи (иначе — ошибка «Запись потеряна»).
- Блокировка сохранена только для фонового монитора рынка (`compute/market_monitor.py`, `tracking/runtime.json`).
- Условие пересмотра: регулярная параллельная работа агентов с частыми записями или хотя бы одна потерянная запись — вернуть блокировку в виде аренды со сроком (блок A аудита).
