# W2-T037: пассивная диагностика выбора шага IAS15

19.10.2026 · owner `pi-w2-b-controller-20261019` · run_id `W2-B-controller-20261019`.

## Область разрешения

Пользователь «продолжай» после C073 поручил следующий шаг: разобрать уменьшение dt и подготовить различающие короткие эксперименты. Этот пакет ограничен чтением сохранённых данных и одним пассивно инструментированным native replay (417 попыток, 60 s внутри / 90 s снаружи; 1 поток; 2 GiB/256 MiB). Никаких изменений силы, координат, времени, библиотеки, epsilon, adaptive_mode или guard. Преобразованные/restart-контроли пока только предложить отдельно.

## Источники и наблюдаемые величины

Входы: snapshot C072 (SHA `9a634be5f9404ed88ccf66839aedc7133f4b38a27520e9d029e31dd78557b52a`) и точный replay C073 (SHA `fd3d85242b86559780fe433d326e7b462d474fbd81d18518049d3a14de71af12`). Орбита ранее изучалась; это разработочный диагностический кейс, не независимая проверка.

Первичный код алгоритма: upstream tag REBOUND 5.1.1, `data/raw/rebound_5_1_1_20261019/integrator_ias15.c`, SHA `7d3038a1f1f6ad079f86dd652d75fe16bea76df8c0ae1df630b6001e4871ef6b`. Версия совпадает с установленной, но происхождение локального binary build из этого тега не доказано; вывод формулы проверяется на фактическом dt.

Installed `integrator_ias15.h` и field descriptors задают размеры буферов. После шага `br` содержит b выполненной попытки, `b` уже предсказан для следующего шага; использовать **br**, не b. `a0` сохраняет ускорение начала шага. Считывать только копии, без записи в native буферы и без дополнительных вызовов сил.

Для каждого тела из a0/br вычислить y2=|a_end|², y3=|jerk*dt|², y4=|snap*dt²|². Для PRS23:

`tau²/dt² = 2*y2 / (y3 + sqrt(y4*y2))`,
`dt_new = dt_done * min(tau/dt) * sqrt7(epsilon*5040)`;

применить правило cap роста ×4 и min_dt из источника. Сохранить определяющее тело, предлагаемые шаги всех тел, y2/y3/y4, геометрию, шаги в единицах ULP времени/положения и iterations_max_exceeded. Последний счётчик не раскрывает число PC-итераций/выход по осцилляции и не доказывает полной сходимости.

## Критерии, зафиксированные до нового replay

1. **Пассивность:** все 416 принятых шагов и 417-й guard совпадают с C073 по прежним точным критериям; любое расхождение делает инструментированный проход непригодным для диагностики исходного replay.
2. **Проверка реконструкции контроллера:** относительное отличие вычисленного next_dt от фактического ≤1e-12 на всех 417 попытках. Это численный допуск реконструкции формулы, не научный допуск траектории.
3. **Геометрическая альтернатива:** показать расстояния и локальный период пробы относительно хозяина при пересечении dt уровней 1000/100/1/1e-3/1e-5 s. Не объявлять столкновение по малому dt.
4. **Гипотеза шума координат/коэффициентов:** показать ULP абсолютных координат и относительное перемещение пробы за dt в этих единицах; рост производных из br при гладкой геометрии согласуется с шумом, но сам по себе не доказывает его источник. Не называть корреляцию причинным экспериментом.
5. **Блокировка шага извне:** сравнить предложенный/запрошенный/dt_done/next_dt и внешний ias15_step_limit; различать внешний clip и уменьшение внутри IAS15. Число внутренних отклонённых попыток текущим ABI не наблюдается.

## Следующие различающие контроли — пока не выполнены

По результату выбрать небольшой разработочный набор: native без изменений как контроль; physical restart без преобразований для отделения адаптивной истории; одинаковый physical restart с отдельно заданным переносом начала координат/галилеевым сдвигом, либо только переносом начала времени. Эти вмешательства требуют отдельной фиксации преобразований, количественных критериев и сравнения при общем времени. Стабильное dt после вмешательства не доказывает точности/production допуска. Guard не ослаблять; не делать вывод, что отказ обязательно исправлен.
