# W2-T004 — аудит и статистический монитор рынка Vast.ai

2026-10-06. Поручение пользователя: глубоко проверить охват CPU из good_cpu.txt,
логирование цены/конфигурации, увеличить **поисковый** предел до $1/h, проверить
работу запросов и подготовить мониторинг на 2–3 дня. Это не разрешение аренды
по $1/h; прежние пределы платной аренды W2-D002 не расширяются.

Текущие дефекты: CPU-only запрос фактически возвращает дисковые контракты;
числовой разбор пропускает первые Core i9/i7 и суффиксы, схлопывает X/X3D;
равенство total/effective CPU исключает пригодные доли; limit=400 не доказывает
полноту; first_seen перезаписывается, reappear/gone не сбрасываются полностью;
ошибки/пропуски сети не должны считаться исчезновением предложений.

Общий read-only collector для обоих CLI: good_cpu.txt сохраняется источником,
каждая модель и указанные семейства проверяются тестами; client match по токенам,
нормализация Intel/AMD/trademark/регистра и Xeon w5/w7/w9. Рынок включает
compute с GPU и настоящий cpu; disk/unknown отклоняются. По умолчанию $1/h
при 20 GiB запрошенного диска, >=4 effective CPU, >=20 GiB доступного диска,
on-demand; shared/full CPU сохраняются отдельно. После уточнения пользователя
обязательное равенство CPU отменено; нижний предел расширен до 1 effective CPU
для сбора статистики, дополнительный фильтр --min-cores остаётся доступным.
Verification/reliability/RAM
логируются, отсутствующее null. Выдача — сведения провайдера, не измеренная
производительность и не гарантия CPU quota.

Поиск без неявных CLI defaults, с явными условиями доступности и amd64.
Если выдача упирается в limit, делить по цене и числу GPU; остаточное ограничение
помечать incomplete. Нельзя обещать абсолютный охват невидимых backend предложений.
Отсутствие при incomplete/error не создаёт gone и не увеличивает знаменатель
наблюдаемой доступности. Записывать запросы/тайминги/ошибки/HTTP429 и backoff,
не печатая key/URL/stderr с секретами. Не искать предел блокировки нагрузочным
штурмом: измерить несколько нормальных циклов, штатный интервал 300 s,
последовательные запросы с минимальным промежутком, экспоненциальная пауза при ошибке.

Сохранять сессию, SHA источника/конфигурации/кода, append-only снимки и события,
SQLite историю наблюдений/запросов, состояние и heartbeat; статистику по моделям,
машинам и выделенной конфигурации, цены base/storage/total отдельно. Число GPU
офферов одного machine не считать числом независимых рабочих станций.
Плановый сбор 48/72 h с ограничением срока/диска и корректным завершением;
на этом поручении — короткий live audit, длительный сбор готовится для запуска позже.

Приёмка: детерминированные тесты охвата и ложных совпадений; disk/unknown/null;
поддержка ошибки 429/timeout/invalid JSON при exit0 без утечки ключей; truncated
выдача; changed/gone/reappeared/restart; stats без ошибок как absence. Затем Ruff,
validate и live read-only запросы с полным журналом. Предположение об отсутствии
блокировки ограничить измеренной серией, не распространять на будущие 72 h.
