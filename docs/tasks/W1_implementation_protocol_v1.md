# W1 — исполняемый протокол v1

Статус: development, не freeze. Согласованная цель: 10000 юлианских лет =
315576000000 s TDB от JD2451545.0; единицы km, s; невращающиеся оси ICRF.
Номинальная L1 v0.4.1 и aligned-v3. Поля/параметры имеют прежние ограничения W0.
Подробная машинная постановка: `configs/sampling/W1_design_v1.yaml`.

## Меры, выборки и знаменатели

Три прямые условные меры: uniform(a,e,cos i,phases), uniform(log a),
канонический объём. e≤0.3, a≤RH0 с множителем 3, буфер контакта 0.02,
радиус пробного тела 0.1 km. Буферы 0/0.05 — отдельные версии сценариев.
Начальные фазы субспутника покрываются генератором; внешняя конфигурация
фиксирована. Устойчивость к внешним фазам этим результатом не проверяется.
Исходная сетка статьи не объединяется с этими мерами.

Пилот: Япет, Ганимед, Гималия, 8 scrambles ×256 точек ×3 меры.
Общие seeds внутри пар хозяев/мер; разные scrambles независимы. Потоки:
pilot=202610051+k, main=203610051+k, coverage=204610051+k.
Индекс k начинается с 0. Основная серия использует новые потоки; изменение
объёма создаёт новый design_id. Прямые выборки имеют p=q и weight=1.
Пропуск записи запрещён: невычисленные старты записываются unresolved.
Адаптивные и контрастные benchmark-случаи не оценивают общую долю.

Основная группа: Япет, Титан, Каллисто, Рея, Ганимед, Феба.
Контроль: Европа, Диона, Гиперион, Гималия. Равный вес хозяев внутри группы.
Разработка H3: только три пилотных хозяина. Holdout H3: Европа, Диона,
Гиперион. Титан/Каллисто/Рея/Феба — сравнения без настройки предсказателя.
Гималия уже разработочная; литературные результаты не являются слепыми.
Непилотные входы ещё требуют допуска: регистрация имён его не заменяет.

## Зарегистрированные правила решений

H1: при каждой мере Δ=mean(main)−mean(control). Семейство 3 сравнений.
supported, если все нижние одновременные границы >0.03;
contradicted, если хотя бы одна верхняя <0.03; иначе inconclusive.

H2: все 15 пар основной группы ×3 меры, семейство 45 сравнений.
Пара поддерживает H2 при одном достоверном знаке во всех мерах либо всех
интервалах внутри [−0.03,0.03]. Противоположные различия >0.03 по модулю
дают contradicted. Общая H2 supported только при всех поддержанных парах;
любое опровержение даёт contradicted, прочие случаи inconclusive.

H3: геометрический прогноз μ{a(1+e)≤c RH0}. Сетка c=0.10:0.05:0.90;
один общий c минимизирует равновесную MSE по 3 хозяевам ×3 мерам разработки.
При равенстве выбирается меньший c. Константа сравнения — средняя доля
разработочных хозяев отдельно для каждой меры. При unresolved подгонка
не разрешена. На 3 holdout сравниваются средние квадратичные ошибки:
Δerror=geometry−constant; семейство 3 мер. supported: все верхние границы
<0; contradicted: хотя бы одна нижняя >0; иначе inconclusive. Разность
квадратов линейна по доле: численный шум y² сокращается. Это вывод для
перечисленных хозяев, не генеральной совокупности спутников. Объяснение
остатка физикой требует W4. c и количественные прогнозы остаются null до
пригодного пилота; затем фиксируются до раскрытия holdout.

## Интервалы, остановка и аварии

Основной безопасный метод v1: Hoeffding по независимым рандомизациям,
поправка Бонферрони отдельно внутри каждого семейства. Для оценок в [a,b]
полуширина (b−a) sqrt(log(2m/α)/(2K)), α=0.05. Общая ошибка сразу по трём
гипотезам не заявляется равной 5%. Статистическая единица — scramble,
не узел Sobol. При unresolved нижний/верхний исход оценивается отдельно.
Парные разности сохраняют общие seeds и ковариацию; отдельные сценарии
не усредняются. Приближённый Student-t остаётся диагностикой, а не
автоматически допущенным интервалом. Нулевой разброс не даёт нулевой ошибки.

Проверка покрытия: независимые development/validation seeds, гладкая,
разрывная, редкая и константные функции с известным интегралом. Регистрировать
число повторов и биномиальные границы частоты покрытия. Это проверка
статистики, не динамическая проверка модели. Теоретическая гарантия Hoeffding
условна на независимость рандомизаций и корректность ограниченных оценок.
Она относится к математическому ожиданию реализованного генератора; ошибку
конечной цифровой сетки и численную ошибку нельзя считать автоматически
покрытыми этим интервалом для непрерывной физической меры.
Основание неравенства: [Hoeffding 1963](https://doi.org/10.1080/01621459.1963.10500830).
Свойства random_base2, LMS+shift и число бит:
[официальная документация SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.qmc.Sobol.html).

Основной объём фиксируется до основных исходов. Для гарантированного метода
K=ceil((b−a)² log(2m/α)/(2h²)); пилот оценивает реальную дисперсию и стоимость,
но не уменьшает этот гарантированный бюджет без новой проверенной версии
интервалов. Цели h=0.01 и численной чувствительности <0.005 не достигнуты
самим выбором конфига. Последовательного просмотра значимости нет.

## События и численный допуск

Контакт — существующий поиск всех минимумов dense-полинома DOP853.
Кандидат операционного ухода: пересечение 2 RH0 наружу; подтверждение после
одного начального периода хозяина без возврата внутрь RH0. Время события —
конец окна; окно за T оставляет unresolved. Чувствительность: внешняя граница
1/3 RH0, окно 0.5/2 периода. Возврат на границе окна отменяет подтверждение.
Знак E2 — диагностика. Временный выход, физический контакт, операционный
уход и вычислительная авария различаются; вечный уход не доказывается.
Разрушение не моделируется номинальной L1 и не подменяется Roche-пересечением.

DOP853 на длинном режиме пока не допущен. Benchmark сохраняет промежуточное
валидное состояние и стоимость даже при лимите времени. Высокие e требуют
отдельного контроля IAS15; прежний V02 не разрешает DOP853 high-e.
State restart начинает новую адаптивную историю; не объявляется точным
продолжением внутреннего состояния интегратора.

## Ресурсы и завершение

Первый benchmark: 3 хозяина ×2 радиальных положения ×3 наклонения ×2 e.
Ограниченный общий запуск, не серия пилотов в обход лимита: ≤600 s,
1 worker/1 thread, 2 GiB, ≤256 MiB выхода. Частичные участки не считаются
доказательством долгой сходимости; экстраполяция стоимости помечается как
предварительная. Полный пилот 18432 интеграций требует отдельного допуска.
При прогнозе >6 h не запускать длинную локальную серию, подготовить предложение
по compute_policy. Расходы требуют прямого разрешения на конкретный план.

Freeze требует полного реального пилота на общем T, проверенных событий,
длительной динамики, стоимости/дисперсии, split, предсказаний и SHA всех
доказательств. Синтетический V06, короткий benchmark и готовый код недостаточны.
production_allowed остаётся false; входы дополнительных хозяев проверяются
перед W3. Все существенные результаты — через track add и claims.csv.

## Исполняемые точки входа

Все команды запускаются Python проекта из корня:
`scripts/verify_w1_statistics.py`, `scripts/verify_w1_restart.py`,
`scripts/benchmark_w1.py`. Они создают новые immutable runs.
`scripts/run_w1_pilot.py --admission <relative.json>` требует численного допуска
с design_id, общим horizon_seconds, integrator=DOP853, audited_inputs,
events_validated, long_dynamics_validated, restart_validated, измеренным
estimated_total_wall_seconds, evidence_sha256 и numeric_options
(rtol, atol_position, atol_velocity, max_step_period_fraction).
Сейчас такого принятого допуска нет; флага обхода нет.
`scripts/analyze_w1.py --pilot-run runs/<id>` проверяет SHA и повторяет
разработочный анализ полного знаменателя. Benchmark и holdout этот CLI
не принимает как разработочный пилот. Вычислительные прерывания сохраняют
partial/unresolved и не создают пригодную для freeze дисперсию.
