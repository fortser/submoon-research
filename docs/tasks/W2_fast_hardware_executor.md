# Единый заранее подготовленный исполнитель аппаратного теста

Зависимость: принятое W2-D043, [компактный протокол](../compute/fast_trial_policy.md). Эта карточка — следующая техническая подготовка, не готовый исполнитель и не разрешение платного запуска. Исторические контроллеры в scratch/evidence не считать универсальным проверенным fast path.

## Цель

Убрать написание скрипта и полную проверку окружения из критического пути после сигнала. Подготовить reusable CLI с отдельными `prepare` (без платных действий) и `run` (только по сохранённому новому сигналу пользователя) командами. Радар не получает аккаунтный ключ и не арендует.

## Обязательные свойства

- Идентификаторы signal/task/run, исходное сообщение, W2-D043 и один расходуемый create-token, устойчивые к повторному запуску/дубликатам. Старые манифесты не перезаписывать. Существующий инстанс с тем же run/label сверять, не создавать второй.
- Prepare заранее проверяет установленный транспорт/SSH/зависимости/probe и сохраняет версии/SHA без секретов. Реальные network gates непосредственно перед create остаются обязательными.
- По конкретной находке — один свежий точечный запрос, без полного sweep; актуальные финансовые/ресурсные gates того же radar.assess, известные тарифы и ограниченный трафик. Аккаунт/оффер проверять параллельно при независимости. Никаких неявных spot/default price/платных замен.
- Create один раз с bounded timeout, без сетевых retry на изменяющей операции. Сохранение очищенного HTTP-статуса/кода ошибки/new_contract (урок T054), ключи/полные тела ответов/секретные URL не журналировать. Timeout неоднозначен: inventory/label reconciliation, не повтор create.
- Дедлайн от начала create, резерв на provisioning/load/download/destroy; runtime с PID исполнителя и instance_id немедленно после подтверждения. Непрерывная цепочка без ожидания сообщений чата. При сбое проявить необходимость вмешательства, не выдавать JSON-бюджет за реальную гарантию остановки.
- Автоматическая аппаратная нагрузка до успешного завершения либо подтверждённого отказа, затем малый download с SHA и destroy только своего ресурса. Не удалять чужие инстансы и не нарушать новые явные инструкции пользователя.
- Краткая диагностика: CPU model/topology/affinity/cgroup CPU/RAM, 1/physical/logical CPU load, ограниченные память/диск, SSH. Не выдавать sysinfo/512 MiB test за проверку всей RAM, disk capacity host за контрактную quota, краткую нагрузку за гарантию эксклюзивности.
- Финальный inventory и ограниченная проверка биллинга, разделяя estimate/счёт/задержку данных. Данные и ошибки сохранять при любом исходе.

## Приёмка без расходов

Офлайн-тесты с полностью подменённым API/SSH/часами: нет сигнала, дубликат сигнала/запусков, stale offer, цена/трафик неизвестны или выше лимита, disk/deverified/excluded, отказ create, timeout после принятия create, provisioning/SSH/probe/download failure, дедлайн, destroy failure, чужие ресурсы. Для каждого сценария утверждать count(create)≤1, отсутствие секретов и корректный runtime/исход. Тесты не вызывают Vast.ai.

Отдельный оплачиваемый контроль разрешается только новым сообщением пользователя о находке по W2-D043; разработка исполнителя его не заменяет. Реальный benchmark «команда → create» пока отсутствует. Цель — сокращение подготовки, не обещание гарантированных секунд или удержания оффера.
