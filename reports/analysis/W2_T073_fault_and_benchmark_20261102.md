# W2-T073 — ошибки файловой публикации и синтетический A/B

Evidence ID `W2-T073_fault_20261102T095023Z`; продолжение [C127](W2_T073_initial_implementation_20261102.md). Это техническая проверка предварительного патча, **не научный допуск и не окончательная приёмка**.

## Сбои fsync/replace

Добавлены шесть сценариев: `fsync`, `os.replace` до фактической замены, `os.replace` после успешной замены; каждый — с успешной и дополнительно отказавшей финализацией. Обёртки `write_json` только определяют фазу, а исключение инъецируется на реальной границе системного вызова внутри неизменённого `atomic_text`. Во всех сценариях тело запуска не исполняется, основное исключение сохранено, повторное исключение доступно через `__cause__`; целостный manifest не заявляет завершённый запуск.

При отказе после уже выполненного replace **и** повторном сбое финализации остаётся `running/complete` с проверенными SHA снимка — это не completed/passed. В остальных случаях при отказавшей финализации остаётся `running/pending`; при работающей финализации — `failed/failed`, без опубликованного частичного индекса. Исключение после успешной замены моделирует неоднозначную границу вызова, не утверждает, что обычный `os.replace` так работает.

Адресные тесты на Windows **23 passed** и Ubuntu-24.04 **23 passed**; включают прежние kill-проверки собственного child. Ruff `src scripts tests` passed. Принудительное завершение и подмена ошибок не доказывают сохранность при отключении питания, аварии ядра или сбое накопителя. Для копий по-прежнему нет отдельного fsync; каталоги не fsync-ятся.

## Мутации

Только в памяти возвращены: (1) публикация после каждого файла, (2) отсутствие сохранённой копии, (3) преждевременный `complete`. По одному выбранному тесту на мутацию: все три дали ожидаемый **1 failure, 0 errors**, скрипт возвращает 0 только при таком результате. Диски с production-файлами не модифицируются.

Первые два диагностических старта per-file сохранены: первый не смог импортировать пакет из `scratch`, второй неправильно вызывал сохранённый указатель на `write_json` и обходил тестовый spy, поэтому ошибочно не обнаружил мутацию. Затем исправлены путь импорта и непосредственный вызов `execution.write_json` в мутанте; успешный контроль — изменённая постановка, результаты до исправления не скрыты. Это проверка конкретных тестов, а не полная mutation coverage.

## Контролируемый A/B на Windows

Сравнены сохранённый до патча `execution_baseline.py.txt` и текущий `execution.py` в отдельных свежих процессах, порядок **A-B-B-A-A-B**, один диск, без очистки кеша. В каждом synthetic workspace одинаковые 50 файлов кода, 21 360 байт; все шесть индексов имеют одинаковый SHA, каждая копия сверена с индексом. A/B действительно запускает прежний код из сохранённой копии, не переключает production-файл. Измеряется `__enter__`, не продолжительность всего запуска.
