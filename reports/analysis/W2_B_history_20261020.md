# W2-T039: native и fresh restart различаются несколькими группами памяти

Фактический аудит **20.10.2026**, завершён в 07:49:43 UTC. Run_id `W2-B-history-20261019` и каталог сохраняют ранее выбранный идентификатор; суффикс даты не является фактической меткой исполнения. Проверка `W2-C078`. **Выполнено 0 интеграционных шагов.**

## Наблюдение

Из одного snapshot C072 загружены native и fresh physical экземпляры. Состояния x/v совпали **побитно**, как и G/число тел/массы/фигуры, t, предложенный dt, epsilon=1e-9, PRS23, min_dt=0, gravity=basic, softening=0 и velocity-independent force flag. Проверка загрузки включает физический контракт и параметры REBOUNDx.

Но внутреннее численное состояние различается:

| Группа | Native | Fresh до первого шага |
|---|---|---|
| b/e/g/br/er | по105 элементов, все ненулевые | NULL / не выделены |
| csb | 41 ненулевой элемент из105 | NULL |
| csx | 15 ненулевых; max abs≈1.42703e-5 km (1.427 cm) | NULL |
| csv | 15 ненулевых; max abs≈7.34462e-16 km/s | NULL |
| csa0 | 15 нулевых элементов | NULL |
| at/x0/v0/a0 | выделены, ненулевые | NULL |
| dt_last_done | 4145.39561957939 s | 0 s |
| steps_done | 6682786 | 0 |

**NULL не объявляется выделенным нулевым массивом.** В начале первого шага исходник IAS15 выделяет/инициализирует рабочие массивы; это пока только сравнение перед исполнением.

Разность csx пробы и хозяина составляет `[-5.76387492401409e-6, -6.777692760806531e-6, 2.589506038930267e-6] km`, то есть несколько миллиметров по компонентам. В predictor исходник использует компенсацию `-csx` до добавления x0. Поэтому совпадение сохранённых binary64 x/v **не означает совпадения низших разрядов компенсированного представления**. Успех P00 после fresh restart нельзя приписать только обнулению полиномиального предиктора.

## Что следует из исходника 5.1.1

- g заново получается из b; csb обнуляется до predictor-corrector.
- При отклонении шага b/e могут восстанавливаться из br/er, если dt_last_done!=0.
- csx/csv участвуют и в предсказании узлов, и в компенсированном обновлении конца шага.
- x0/v0/a0 и at — рабочие данные, перезаписываемые в начале/внутри шага.
- При фактическом gravity=basic csa0 обнуляется; отдельный перенос компенсации гравитации не требуется для этой постановки.

Это обосновывает разделение групп в [предложенном W2-P012](../../docs/tasks/W2_B_memory_controls_v1.md): M0 без вмешательств, MP полиномиальная память, MC csx/csv, MD dt_last_done, MA их сочетание. **Resets ещё не выполнялись.**

## Верификация чтения

Первое чтение через публичный Python getter остановилось на NULL-указателе fresh: REBOUND 5.1.1 пытается создать `int(None)` и поднимает TypeError. Ни шагов, ни изменений памяти не было; неуспешные command/stdout/stderr/execution сохранены.

После чтения установленных `integrator.py`, `binarydata_field_descriptor.py` и `integrator_ias15.h` указатели прочитаны напрямую по проверенным field descriptors (offset/offset_N), без записи. N_allocated проверен до чтения массивов; fresh NULL не разыменовывается. Второй read-only аудит завершён успешно за **2.531 s**, 1 CPU/поток, RLIMIT_AS 2 GiB, внешний timeout≤60 s. Библиотеки и production-код не правились.

[Полный audit.json](../../results/evidence/W2_B_history_20261019/audit.json), команды `command.json` / `command_v2.json`, execution/logs и package manifest в том же каталоге. Значения всех буферов сохранены, не только максимумы.

## Ограничения

Наблюдение различий памяти не доказывает причину отказа. Полиномиальная группа, компенсационные остатки и dt_last_done ещё не разделены экспериментально. Удаление csx/csv изменяет скрытое численное представление состояния; его нельзя назвать физически нейтральным лечением. Готовность production B, W1/W3 и checkpoint событий не получена. Проблема Windows timeout I037 сохраняется отдельно; read-only аудит её не проверял.
