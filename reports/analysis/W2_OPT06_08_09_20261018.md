## 1. OPT-06: приёмка по буквальным входам отдельно от проверки генератора

Добавлены `contracts/frozen_p2.py` и `scripts/freeze_p2_inputs.py`; стенд и приёмщик P2-2 поддерживают:

```text
--inputs-manifest <путь>/inputs_manifest.json --inputs-manifest-sha256 <внешний SHA-256>
```

Порядок доверия: **SHA манифеста, закреплённый вне проверяемого артефакта → SHA units.json → схема/состав/полный контракт → параметры и численный режим задания → fingerprints результатов**. Проверяются размерности, конечность, уникальность, ячейки/seeds фиксированной версии P2-2-v1. Самопровозглашённого SHA внутри JSON недостаточно.

В этом режиме генератор не вызывается. Проверка генератора вынесена в `freeze_p2_inputs.py --check-generator ... --manifest-sha256 ...`; её провал не подменяет проверку ранее зафиксированного расчёта. Без внешнего якоря прежний маршрут явно называется **generator regression**, а не frozen-input acceptance. Новые run сохраняют локальные units/manifest; исходный отдельный артефакт входов не изменяется, выходы не могут быть вложены в него.

### Ограничение исторической реконструкции

Экспортёр требует внешние SHA исторических summary/jobs и совпадение каждого ожидаемого fingerprint **до создания артефакта**. Реконструкция девяти ячеек j=8 P2-2a в локальном AVX2-окружении отклонена на `iapetus:uniform_a_e_cos_i_phases:0008, D, 1000`: [лог](../../results/evidence/W2_OPT06_08_09_20261018/historical_reconstruction_rejected.log). Каталог исторического артефакта не создан. SHA/fingerprint не ослаблялись.

Это согласуется с известной зависимостью legacy-BLAS от ядра, но новых сравнений BLAS-ядер здесь не проводилось. CPU — i5-9400, AVX2, без AVX-512 ([lscpu](../../results/evidence/W2_OPT06_08_09_20261018/wsl_cpu.txt)); SkylakeX принудительно не включался. **Полная историческая frozen-реконструкция остаётся открытой**, требуется подтверждённый исторический маршрут. Наличие нового переносимого формата не меняет идентичность старого run.

## 2. OPT-08: пассивная диагностика, входной отказ и снимок до шага

`diagnostics/ias15_replay.py` оборачивает неизменённый `NativeIAS15.step`; реализация B и её fingerprint не меняются. Отдельно маркируются: граница не впереди, отсутствие продвижения времени, превышение границы, несогласованный dt_done, остаток полинома и прочие исключения. Это диагностическая классификация существующих guards, не изменение их допусков.

Кольцевой буфер (по умолчанию 128, максимум 1000 записей) хранит предложенный/ограниченный/выполненный/следующий шаг, границу, ULP времени, epsilon/min_dt/adaptive_mode, счётчик iterations_max_exceeded, минимальное расстояние всех пар, масштаб абсолютных координат, остаток dense-полинома и SHA состояния/коэффициентов. Запись можно ограничить временным окном.

По условию времени либо малого предложенного шага **до вызова шага** сохраняется один новый snapshot: полное физическое состояние всех тел, GM/фигуры/система координат, время/dt/настройки; отдельные бинарные REBOUND Simulationarchive и REBOUNDx; manifest с SHA, окружением и исходным B-контрактом. Бинарный снимок хранит внутреннюю историю IAS15; скалярные поля отчёта не объявляются полной оценкой ошибки внутри predictor-corrector.

`diag_b_failure_p2_2.py` теперь **отказывает до интеграции**, если не совпали внешние SHA source summary/jobs, выбранный job fingerprint, реализация B или точный исходный probe. Есть `--preflight-only`. В штатном коротком маршруте максимум 600 s, по умолчанию 60 s; часовой проход этим интерфейсом сейчас не разрешён. Остановка бюджетом — `partial`, код 1, а не успешная интеграция или повтор научного отказа.

### Что НЕ доказано

Старый отказ произошёл при `t=25526330757.864594 s`, после 6 683 202 принятых шагов. Проверены фактические файлы `runs/W2-P2-2a-56220810/` и `results/evidence/W2_I034_diag_20261017/`: там нет полного pre-failure state/native snapshot. Старый кольцевой журнал содержит времена/шаги/радиус, но не внутреннюю историю и не состояния всех тел. Из него точный replay построить нельзя.

Поэтому **короткий replay исторического отказа пока не получен**. Новый снимок относится к начальному участку, не к окну отказа. Пассивность обёртки, J2-параметры REBOUNDx и native-сохранение проверены коротко; универсальная побитовая переносимость между другими сборками/CPU не заявляется. Снимок не включает EscapeTracker/историю всех событий исполнителя: это не production checkpoint или сквозной W1 restart.

## 5. Следующий шаг — только после отдельного согласия

Для данных **перед старым отказом**, а не ещё одного бесполезного повтора, предлагается одна локальная диагностическая попытка:

- та же орбита и B-контракт, исходное время/координаты/guard/силы без изменений;
- один worker/поток, текущее WSL-окружение, до 2 GiB RAM и 256 MiB выходов;
- снимок до шага при первом `t >= 25525800000 s`, кольцевой журнал последних 512 шагов; затем исход до guard либо установленного бюджета;
- ориентир по прежнему измерению — около часа (старый проход 3438.55 s); предложенный жёсткий предел — **90 минут**, одна попытка, без автоматических повторов;
- это требует отдельного разрешения на длительность и отдельного ограниченного профиля запуска сверх нынешних 600 s. Сейчас такое исключение не включено, общие лимиты не расширены;
- после получения снимка — короткий native replay без изменения метода, затем только различающие диагностические эксперименты по отдельной постановке;
- аренда, расходы, смена библиотек, исправление B, перенос времени/координат, high-e fallback и новый ансамбль **не входят**.

Стоп-точка текущего пакета: передать эти результаты пользователю и запросить согласие на конкретную одну длительную диагностическую попытку. Не запускать её по одному слову «продолжай» в рамках прежнего разрешения короткого пакета.
