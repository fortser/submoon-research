# W2-T072: доступность наблюдения процесса Windows

Дата 01.11.2026 UTC. Owner `pi-c120-attribution-20261101T100324Z`. Научные расчёты и исходный pytest не запускались.

## Проверено

1. Параметры журнала `Microsoft-Windows-Kernel-Process/Analytic` прочитаны командой `wevtutil gl`: канал **выключен**. Он не включался; параметры системы, журналы и политика аудита не менялись. Его текущее состояние не позволяет восстановить отсутствие/наличие событий в исторический момент.
2. Подписка WMI `Win32_ProcessStartTrace` временно создана на период безопасной локальной пробы. Запущен только собственный `cmd.exe /d /c exit 0`; из входящего потока сохранялась только запись с PID именно этого child. Событие получено: PID 19796, ParentProcessID 14960, имя cmd.exe; child завершился с кодом 0. Подписка и сообщения удалены штатно. Другие события не сохранялись.
3. В полученном событии **нет свойства CommandLine**. По этой пробе WMI может помочь наблюдать parent PID, но не позволяет определить, с каким `-d` запускался wsl.exe. Непосредственный запрос живого процесса может не успеть для короткоживущего launcher и требует отдельной проверки; отсутствие аргументов нельзя трактовать как отсутствие `-d`.

Доказательства: `results/evidence/W2_T072_attribution_20261101T100324Z/kernel_channel.txt`, `wmi_probe.json`; скрипт собственного безвредного контроля: `scratch/W2_T072_wmi_probe_20261101T100324Z.ps1`. Информация о чужих command line, секретах и окружениях не записывалась. Процессы других пользователей/WSL не завершались.

## Вывод и границы

Данные C121 не содержат исторических аргументов, parent-child ребер и Linux PID. **Кто вызвал исторические wsl.exe и какой дистрибутив был выбран, установить нельзя** по имеющемуся набору. Текущая подписка WMI не восстанавливает историю. Дистрибутив Ubuntu сейчас выбран по умолчанию, но это не доказывает выбор или сам запуск в прошлой пробе.

Доступность WMI-подписки и PID события проверена только на одном собственном cmd.exe. Это не полная трассировка всех процессов, не гарантия получения событий при нагрузке и не гарантированная cleanup Linux-потомков. До безопасного контроля всех потенциальных Linux-потомков исходный pytest, способный породить WSL, не повторялся. Текущая причина C120 и влияние порядка остаются неизвестными. Независимый review отложен по D049, не пройден.
