Прямое поручение пользователя: «арендуй для тестов», в ответ на оффер 54621118, machine 153489. Оператор объявил одну попытку, до 30 минут и $1, аппаратную проверку без научной серии, затем удаление. Это новое поручение, не повтор W2-D031 и не согласие на B144.

## Фактическая последовательность

- Предпроверка: оффер доступен, $0.6588888889/ч с 60 ГБ, CPU API 192 vCPU, RAM API 515223 MB, unverified, ставки трафика проверены. `preflight.json`, `offer.json`.
- Создан единственный instance **57038234**. Начало вызова create 2026-10-21 10:28:59.878 UTC, ответ create сохранён 10:29:01.524 UTC. Образ `python:3.11-slim-bookworm`.
- В 10:29:58 UTC API подтвердил running. SSH аутентификация успешна, но noninteractive exec возвращал `no sessions / open terminal failed: not a terminal`; SFTP прерывался EOF.
- Причина — автоматическое открытие tmux образом. Через интерактивный SSH штатно создан маркер `~/.no_auto_tmux`, получен `AUTO_TMUX_DISABLED`. Изменён только созданный этим разрешением инстанс.
- После ожидания продолжения диалога следующая попытка `probe` не дошла до SSH/нагрузки: локальное условие предельного ожидания уже истекло. В 11:07:44 UTC проверено: прошло 38.74 мин, установленный оператором 30-минутный срок уже превышен. Независимого исполнителя контроля срока не было; этот способ ведения аренды оказался ненадёжен.
- Оператор сообщил о прекращении теста и вызвал finish. **Удаление завершено и отсутствие проверено в 11:07:58.521 UTC**, `rental.json`, `instances_after_destroy.json` (пустой список). runtime-запись этой аренды удалена. Чужие инстансы не изменялись.
- После завершённого destroy пользователь указал дважды: «не нужно удалять пока не проведешь нагрузочный тест». Указание получено после необратимого удаления; восстановить контракт нельзя. Оператор признал ошибку незавершения теста до удаления. Новая оплачиваемая попытка не предпринималась; требуется новое явное разрешение.

**Пригодность не установлена.** Реальные CPU affinity/cgroup/quota, RAM, нагрузка, память и диск не измерены. Научный расчёт не запускался. Файл `hardware_probe.py` — подготовленный скрипт, не свидетельство выполнения. Обещанный оператором 30-минутный срок не выдержан.

Следующий шаг: по явному согласию пользователя перепроверить оффер и провести одну новую аренду с непрерывным выполнением нагрузки, не прекращая её только из-за прежнего 10-минутного окна provisioning.
